# Phase 15.5: WordPress Site Import Engine - Context

**Gathered:** 2026-04-28
**Status:** Ready for planning

<domain>
## Phase Boundary

WordPress sitesindeki mevcut içeriği **read-only** olarak içe aktarmak, normalize etmek, GSC verisiyle URL bazlı eşleştirmek ve her sayfa için SEO audit flag'leri hesaplamak.

**Kapsam:** CONNECT → IMPORT → NORMALIZE → MAP → AUDIT READY

**Kesinlikle kapsam dışı:**
- WP'ye herhangi bir yazma / overwrite işlemi
- Push / publish / update operasyonları (sonraki faz)
- Yeni WP credential UI'ı (Phase 13 altyapısı kullanılır)

</domain>

<decisions>
## Implementation Decisions

### Scope & Architecture
- **D-01:** Sistem tamamen read-only — WP REST API'den yalnızca veri çekilir, WP'ye hiçbir yazma yapılmaz.
- **D-02:** `project_imported_pages` yeni ve ayrı bir tablo — `page_packages` ile karışmaz; "imported vs generated" ayrımı nettir.
- **D-03:** WP credentials Phase 13'ten devralınır (Vault'ta URL + Application Password). Yeni credential UI eklenmez.

### AI Enrichment
- **D-04:** Enrichment import sonrası toplu çalışır — tüm sayfalar önce DB'ye yazılır, sonra tek bir toplu Claude çağrısıyla `content_summary` ve `primary_intent` üretilir. Kullanıcı import biter bitmez tree'yi görebilir; AI sonuçları birkaç dakika içinde eklenir.
- **D-05:** Model = `claude-haiku-4-5`, sayfa başına tek çağrı. 100 sayfa ≈ $0.05 maliyet hedefi.
- **D-06:** `content_summary` = 200 karakter max. `primary_intent` = informational | commercial | transactional | navigational enum.

### Import UX
- **D-07:** Import sırasında inline progress bar gösterilir — '47/120 sayfa içe aktarıldı' mesajı, aynı sayfada. Import bitince 'Site analizine git →' butonu görünür. SSE veya polling ile güncellenir.
- **D-08:** Endpoint sırası: `/wp/v2/pages` → `/wp/v2/posts` → `/wp/v2/categories` → `/wp/v2/tags`. Pagination (`per_page=100`, sayfalama loop) zorunlu.

### Re-import Davranışı
- **D-09:** Re-import = upsert (wp_id bazlı). Aynı `wp_id` varsa güncelle, yoksa ekle. WP'de silinen sayfalar DB'den silinmez — `orphan` flag'i eklenerek işaretlenir. Veri kaybı yok.

### Audit Flag Eşikleri
- **D-10:** `weak_page` = son 28 günde GSC tıklaması < 10 AND ortalama pozisyon > 20. GSC verisi yoksa flag `null` (hesaplanamaz).
- **D-11:** `outdated_content` = WP `modified` tarihi 12 aydan eski. WP REST API `modified` field'ından hesaplanır.
- **D-12:** `orphan_page` = `parent_wp_id` null AND WP menüsünde linklenmiyor. WP REST API `parent` + `menu_order` field'larından hesaplanır.
- **D-13:** Diğer flag'ler: `missing_metadata` (WP yoast_title/meta eksik), `missing_target_keyword` (imported page ile hiçbir keyword_clusters eşleşmesi yok), `duplicate_intent` (AI primary_intent aynı olan 2+ sayfa aynı cluster'a bakıyor).

### GSC URL Eşleştirme
- **D-14:** Eşleştirme zinciri: `imported_page.link` (WP `link` field) ↔ `page_packages.wp_post_url`. URL normalization: trailing slash normalize, https/http normalize, www/non-www normalize. Eşleşme bulunamazsa GSC metrikleri null.
- **D-15:** Alternatif eşleştirme: GSC property URL'i ile imported page link domain karşılaştırması — property match olmayan sayfalar için GSC verisi bağlanmaz.

### Site Analizi UI — `/projeler/[id]/site-analizi`
- **D-16:** Layout = collapsible indent'li liste (tree view). Parent → child indent ile gösterilir. Mevcut site blueprint tree pattern'ine benzer.
- **D-17:** Her satırda: sayfa başlığı + URL + audit flag rozetleri + GSC tıklama + ort. pozisyon. GSC verisi yoksa '—' gösterilir.
- **D-18:** Audit flag filtreleme = üstte toggle chip'leri (multiselect). Chip'ler: Orphan | Weak | Outdated | Missing Meta | Missing Keyword | Duplicate Intent. Aktif filtreler mavi, pasifler gri. İzleme sayfasındaki period tab pattern'ine benzer.
- **D-19:** ProjectNav'a 'Site Analizi' item eklenir (İzleme'nin ardından).

### Claude's Discretion
- WP REST API rate limiting: istekler arası bekleme süresi ve retry mantığı Claude'un takdirine bırakılmıştır.
- `missing_metadata` flag için tam olarak hangi WP field'larının kontrol edileceği (yoast, rank math, native WP title/excerpt) Claude araştırır.
- GSC URL normalization'ın edge case'leri (query string, anchor, subdirectory) Claude'un takdirine bırakılmıştır.

</decisions>

## Existing Code Insights

### Reusable Assets
- `src/lib/supabase/vault.ts`: WP credentials Vault'tan okunur — yeni bir vault.get(projectId, 'wp_credentials') çağrısıyla URL + password alınır.
- `src/lib/supabase/server.ts` `createClient()`: Tüm DB operasyonları user-scoped client ile yapılır (RLS).
- `src/app/(dashboard)/projeler/[id]/ProjectNav.tsx`: 'Site Analizi' item buraya eklenir.
- Mevcut `Badge` bileşeni (`@/components/ui/badge`): Audit flag rozetleri için (className-direct color convention).
- Mevcut `Table` bileşeni: Flat list görünümü için.

### Established Patterns
- WP publish (Phase 13): REST API → `Authorization: Basic base64(username:app_password)` header pattern — import için aynı auth kullanılır.
- GSC sync (Phase 14): Pagination loop pattern (`?per_page=100&page=N`) — WP import için aynı pattern geçerli.
- Server Actions: Tüm mutation'lar server action olarak yazılır (import trigger dahil).
- Türkçe UI metinleri convention: Tüm kullanıcıya gösterilen string'ler Türkçe.

### Integration Points
- `projects` tablosu: `gsc_property_url` (GSC bağlı mı?), WP credentials Vault'ta proje ID'si üzerinden.
- `gsc_metrics` → URL eşleştirmesi: `page_packages.wp_post_url` üzerinden `imported_pages.link` ile join — bu chain Phase 15 aggregation.ts'de kullanılıyor.
- Import butonu: Proje detay sayfasında (`src/app/(dashboard)/projeler/[id]/page.tsx`) veya ayrı bir 'Site Analizi' tab'ında tetiklenir.

### New Table Required
`project_imported_pages` tablosu aşağıdaki alanları içermelidir (minimum):
- id, project_id, wp_id (UNIQUE per project), wp_type (page|post)
- title, slug, link (public URL), parent_wp_id
- wp_created_at, wp_modified_at
- content_summary (TEXT, 200 char), primary_intent (ENUM)
- gsc_clicks, gsc_impressions, gsc_avg_position (nullable — eşleştirme sonucu)
- flag_orphan, flag_weak_page, flag_outdated, flag_missing_metadata, flag_missing_keyword, flag_duplicate_intent (BOOLEAN)
- imported_at (TIMESTAMPTZ), updated_at

<specifics>
## Specific Ideas

- Progress bar mesajı: "47/120 sayfa içe aktarıldı" — numeric progress, kullanıcı siteyi tanır.
- Re-import case: WP'de silinen sayfalar `flag_orphan = true` ile işaretlenir — "WP'de artık yok" bilgisi korunur.
- Audit flag chip renkleri: Orphan = sarı, Weak = kırmızı, Outdated = turuncu, diğerleri = gri.
- AI enrichment sırası: DB write → toplu Haiku çağrısı → DB update (summary + intent). Hata olursa sayfa AI alanları null kalır, import başarılı sayılır.

</specifics>

<deferred>
## Deferred Ideas

- **WP menü yapısını içe aktarma (navigation tree):** WP menu endpoint'lerinden tam navigasyon ağacını import etmek ayrı bir phase scope olabilir.
- **İçerik güncelleme önerisi (Recovery bağlantısı):** Weak + outdated page'lerin otomatik güncelleme görevi açması Phase 16 Recovery Engine'de olacak.
- **Toplu intent override:** Kullanıcının AI intent tahminini manuel düzeltmesi — Phase 15.5 scope'unda değil.
