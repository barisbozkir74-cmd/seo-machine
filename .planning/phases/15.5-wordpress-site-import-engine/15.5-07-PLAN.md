`actions.ts` dosyasının sonuna `startSiteImport` Server Action ekle. Bu action SADECE import'u tetikler — loop burada çalışmaz (Pitfall 1):

```typescript
// Mevcut actions.ts sonuna ekle:

export async function startSiteImport(projectId: string): Promise<{ jobStarted: boolean; error?: string }> {
  'use server'
  const supabase = await createClient()
  const { data: { user } } = await supabase.auth.getUser()
  if (!user) return { jobStarted: false, error: 'Oturum bulunamadı' }

  // Ownership check
  const { data: project } = await supabase
    .from('projects')
    .select('id')
    .eq('id', projectId)
    .eq('user_id', user.id)
    .single()
  if (!project) return { jobStarted: false, error: 'Proje bulunamadı' }

  // import_status = 'running' — Route Handler bunu 'running' olarak güncelleyecek
  // Burada sadece fire & forget ile Route Handler'ı tetikle
  // RESEARCH.md Pitfall 1: Uzun loop Route Handler'da çalışmalı
  const baseUrl = process.env.NEXT_PUBLIC_SITE_URL ?? process.env.VERCEL_URL
    ? `https://${process.env.VERCEL_URL}`
    : 'http://localhost:3000'

  // Fire & forget — await etmiyoruz
  fetch(`${baseUrl}/api/wp/import`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ projectId, userId: user.id }),
  }).catch(err => console.error('[startSiteImport] fire&forget failed:', err))

  return { jobStarted: true }
}
```

**Not:** `NEXT_PUBLIC_SITE_URL` veya `VERCEL_URL` env var kullanımı — yerel geliştirmede `http://localhost:3000`, Vercel'de otomatik. Eğer proje `NEXT_PUBLIC_SUPABASE_URL` benzeri bir site URL env var'ı kullanıyorsa aynısını kullan.

- `error`: string | null

Polling effect (D-07, 500ms):
```typescript
useEffect(() => {
  if (status !== 'running' && status !== 'enriching') return
  const interval = setInterval(async () => {
    const res = await fetch(`/api/wp/import-status?projectId=${projectId}`)
    const data = await res.json()
    setStatus(data.status)
    setCurrent(data.current)
    setTotal(data.total)
    if (data.status === 'complete' || data.status === 'error') {
      clearInterval(interval)
    }
  }, 500)
  return () => clearInterval(interval)
}, [status, projectId])
```

UI render kuralları (UI-SPEC Interaction States):
1. `hasWpCredentials=false` → disabled açıklama + "WordPress bağlantısı yapılandırılmamış..." metni
2. `status='idle'` ve hiç import yok → primary "WordPress Sitemi İçeri Al" butonu
3. `status='idle'` ve önceki import var (importCompletedAt != null) → outline "WordPress Sitemi Yenile" + son import tarihi caption + "Site Analizine Git →" linki
4. `status='running'` → progress bar + "{current}/{total} sayfa içe aktarıldı" + disabled buton
5. `status='enriching'` → progress bar 100% + "Sayfalar analiz ediliyor..." + disabled buton
6. `status='complete'` → yeşil `aria-live="polite"` banner "İçe aktarma tamamlandı" + "Site Analizine Git →" primary butonu
7. `status='error'` → `text-xs text-destructive` hata metni + "Tekrar Dene" outline butonu

Badge renkleri (UI-SPEC §Color):
- running/enriching → `bg-slate-800 text-slate-400`
- complete → `bg-emerald-500/20 text-emerald-400 border-emerald-500/30`
- idle (WP bağlı) → badge yok veya `bg-slate-800 text-slate-400`
