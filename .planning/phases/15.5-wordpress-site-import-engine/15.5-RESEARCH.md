## Summary

Phase 15.5, mevcut bir WordPress sitesinin tüm içeriğini WP REST API üzerinden okuyarak SEO analizi için hazırlayan bir import pipeline'ıdır. Pipeline beş adımdan oluşur: CONNECT (Vault'tan credentials okuma) → IMPORT (pages/posts/categories/tags pagination loop) → NORMALIZE (project_imported_pages tablosuna upsert) → MAP (GSC URL eşleştirmesi) → AUDIT READY (flag hesaplama + AI enrichment).

Projenin mevcut codebase'i bu fazın tüm yapı taşlarını zaten içermektedir: WP credentials vault.ts'te okunuyor (Phase 13), GSC pagination loop gsc/sync/route.ts'te mevcut, URL join pattern aggregation.ts'te belgelenmiş, tree rendering site-blueprint/page.tsx'te flattenTree() ile çalışıyor. Bu faz büyük ölçüde bu pattern'ların birleştirilmesinden oluşuyor.

Import işlemi uzun sürebileceği (100+ sayfa) için progress tracking kritik önem taşıyor. Sistem Server Action + DB state polling pattern kullanacak: import state (current/total) DB'deki projects tablosuna veya ayrı bir import_jobs kaydına yazılıyor; client 500ms aralıklarla polling yapıyor. SSE Next.js 15 App Router'da Route Handler ile destekleniyor ancak Server Action'dan tetiklenemiyor — polling daha temiz.

**Primary recommendation:** Import logic'i tek bir `/api/wp/import` Route Handler'a taşı (uzun-süreli işlem için), state'i DB'ye yaz, client 500ms polling yapsın. Server Action sadece import'u başlat ve jobId döndürsün.

### Pattern 1: WP REST API Pagination Loop

**What:** WP REST API `per_page=100` ile sayfalama — her endpoint için total count `X-WP-Total` header'dan okunur.
**When to use:** 100'den fazla içerik olabilecek her endpoint (pages, posts, categories, tags).

```typescript
// [VERIFIED: codebase analog — gsc/sync/route.ts pagination pattern]
// WP REST API'de toplam sayfa X-WP-Total response header'ında gelir
async function fetchAllWpContent(
  wpUrl: string,
  appPassword: string,
  endpoint: 'pages' | 'posts' | 'categories' | 'tags'
): Promise<WpItem[]> {
  const authHeader = 'Basic ' + Buffer.from(`admin:${appPassword}`).toString('base64')
  const results: WpItem[] = []
  let page = 1
  let totalPages = 1

  do {
    const res = await fetch(
      `${wpUrl}/wp-json/wp/v2/${endpoint}?per_page=100&page=${page}&_fields=id,title,link,slug,parent,date,modified,status,menu_order,yoast_head_json`,
      {
        headers: {
          Authorization: authHeader,
          'Content-Type': 'application/json',
        },
        // Rate limit önlemi: Node.js fetch ile timeout
        signal: AbortSignal.timeout(30_000),
      }
    )

    if (!res.ok) throw new Error(`WP API error: ${res.status} ${endpoint}`)

    if (page === 1) {
      totalPages = parseInt(res.headers.get('X-WP-TotalPages') ?? '1', 10)
    }

    const items = await res.json()
    results.push(...items)
    page++
  } while (page <= totalPages)

  return results
}
```

### Pattern 3: URL Normalization

**What:** imported_pages.link ↔ GSC URL'lerini normalize ederek join yapma.
**When to use:** GSC metrics bağlanırken.

```typescript
// [VERIFIED: codebase — aggregation.ts URL join analogy]
function normalizeUrl(url: string): string {
  let normalized = url.trim().toLowerCase()
  // https/http normalize
  normalized = normalized.replace(/^http:\/\//, 'https://')
  // www/non-www normalize
  normalized = normalized.replace(/^https:\/\/www\./, 'https://')
  // trailing slash
  if (normalized.endsWith('/') && normalized !== 'https://') {
    normalized = normalized.slice(0, -1)
  }
  // query string ve fragment kaldır
  normalized = normalized.split('?')[0].split('#')[0]
  return normalized
}
```

### Pattern 4: flattenTree() Analog (Import)

**What:** parent_wp_id ilişkisini çözerek depth-ordered liste üretme.
**When to use:** SiteAnaliziPage'de tree render için.

```typescript
// [VERIFIED: codebase — site-blueprint/page.tsx flattenTree() — EXACT SAME PATTERN]
// parent_wp_id null = root sayfa
function flattenImportedTree(pages: ImportedPage[]): ImportedPageWithDepth[] {
  const childrenMap: Record<string, ImportedPage[]> = {}
  for (const page of pages) {
    const key = page.parent_wp_id?.toString() ?? '__root__'
    if (!childrenMap[key]) childrenMap[key] = []
    childrenMap[key].push(page)
  }
  function walk(parentKey: string, depth: number): ImportedPageWithDepth[] {
    const children = (childrenMap[parentKey] ?? []).sort((a, b) => a.wp_id - b.wp_id)
    return children.flatMap(child => [
      { ...child, depth },
      ...walk(child.wp_id.toString(), depth + 1),
    ])
  }
  return walk('__root__', 0)
}
```

### Anti-Patterns to Avoid

- **Server Action'da uzun WP import loop çalıştırma:** Next.js Server Action'lar Vercel'de 60s timeout sınırına tabidir. 100+ sayfa loop bu süreyi aşabilir. Import logic'i Route Handler'a taşı, Server Action sadece tetikleyen olsun.
- **SSE (EventSource) kullanmak:** Proje pattern'larında SSE yok; polling tutarlı ve test edilmesi kolay. SSE Route Handler'ın açık kalması Vercel'de sorunlu olabilir.
- **Her sayfa için ayrı DB write:** Toplu upsert (100 kayıt) çok daha hızlı. Batch boyutunu 100 olarak tut.
- **User-scoped Supabase client ile toplu upsert:** RLS her row için policy check çalıştırır. Service role client kullan (vault.ts örneği gibi).
- **_fields parametresini atlamak:** WP REST API full response çok büyük (içerik HTML dahil). `_fields=id,title,link,slug,parent,date,modified,status,menu_order,yoast_head_json` ile sadece ihtiyaç duyulanlar.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Base64 auth encoding | Custom encoder | `Buffer.from(...).toString('base64')` | Node.js built-in, edge case yok |
| URL normalization | Regex chain | `new URL(str)` objesi + custom normalize | URL parse hataları için native URL API |
| Rate limit retry | Recursive retry loop | Exponential backoff (50ms × attempt²) | WP siteleri DDoS koruması var |
| Tree flattening | Recursive custom algo | flattenTree() pattern — site-blueprint/page.tsx | Zaten test edilmiş, EXACT COPY |
| GSC aggregation | Yeni aggregation.ts | aggregation.ts pattern'ını genişlet veya kopyala | GSC URL eşleştirme analogy buradan |

**Key insight:** Bu fazda custom algorithm gereken tek alan `computeAuditFlags()` pure fonksiyonudur; diğer tüm problemler için proje codebase'inde zaten çalışan analog mevcuttur.

## Common Pitfalls

### Pitfall 1: Server Action 60s Timeout

**What goes wrong:** `startSiteImport` Server Action içinde WP pagination loop başlatılır; 100 sayfa = 5-10 dakika; Vercel timeout'a düşer.
**Why it happens:** Server Action execution süresi Vercel Pro'da 300s, hobby'de 60s.
**How to avoid:** Server Action sadece `import_status='pending'` yazar ve `/api/wp/import` Route Handler'ı fire & forget ile tetikler. Import tüm çalışmasını Route Handler'da yapar.
**Warning signs:** `Error: FUNCTION_INVOCATION_TIMEOUT` ya da kullanıcının progress bar'ın takılı kaldığını bildirmesi.

### Pitfall 2: WP REST API `_fields` Eksikliği

**What goes wrong:** WP sayfalar için full response istenirse `content.rendered` HTML'i gelir — megabyte'larca veri; slow fetch, büyük DB write.
**Why it happens:** WP REST API default olarak tüm alanları döndürür.
**How to avoid:** Her endpoint için `?_fields=id,title,link,slug,parent,date,modified,status,menu_order,yoast_head_json` query parametresi ekle. Content HTML'ini asla çekme.
**Warning signs:** Sayfa başına 50KB+ response, yavaş import.

### Pitfall 3: missing_metadata Flag — WP Yoast Field

**What goes wrong:** Yoast SEO eklentisi kurulu olmayan WP sitelerinde `yoast_head_json` field'ı gelmez; null check yapılmazsa TypeError.
**Why it happens:** WP REST API'de `yoast_head_json` register edilmemiş field null değil, eksik olarak gelir.
**How to avoid:** `missing_metadata` flag'ini üç kademeli kontrol et:
1. `yoast_head_json?.title` veya `yoast_head_json?.description` (Yoast)
2. Native WP `excerpt.rendered` (yerleşik excerpt = meta description analog)
3. Her ikisi de yoksa `flag_missing_metadata = true`

Bu Claude'un discretion alanı — aşağıdaki yaklaşım önerilir.

### Pitfall 4: orphan_page Flag — menu_order vs. Actual Menu

**What goes wrong:** `menu_order > 0` olan bir sayfa menüde olmayabilir; gerçek "menüde mi?" sorusu WP REST API `/wp/v2/menus` endpoint'inden gelmesi gerekir.
**Why it happens:** WP'de `menu_order` sadece sitenin içerik sıralaması, global menü navigasyonunu göstermez.
**How to avoid:** CONTEXT.md D-12'yi basit tutarak uygula: `parent_wp_id IS NULL AND menu_order = 0` = potansiyel orphan. Gerçek navigasyon menüsü kontrolü deferred (Deferred listede). Bu eşik yeterli sinyal verir.
**Warning signs:** Ana sayfanın orphan görünmesi — root page `parent=0` ve genellikle `menu_order=0`.

### Pitfall 5: GSC URL Matching — sc-domain: Property

**What goes wrong:** GSC property `sc-domain:example.com` formatında olabilir; bu durumda `gsc_metrics` kayıtlarında URL yerine domain şeması var. URL bazlı join çalışmaz.
**Why it happens:** GSC domain properties page-level URL yerine domain-level data saklar.
**How to avoid:** `projects.gsc_property_url` değerini kontrol et; `sc-domain:` ile başlıyorsa GSC metrics join'i atla, GSC alanlarını null bırak.

### Pitfall 6: Duplicate Intent Flag — Hesaplama Sırası

**What goes wrong:** `duplicate_intent` flag'i AI enrichment tamamlanmadan hesaplanamaz; eğer sıra yanlış kurulursa tüm sayfalar `duplicate_intent=false` kalır.
**Why it happens:** AI enrichment asenkron; DB'ye yazılmadan önce flag hesaplanmaya çalışılır.
**How to avoid:** Audit flag hesaplamasını iki aşamaya böl:
- **Faz A (import biter bitmez):** `flag_orphan`, `flag_outdated`, `flag_missing_metadata`, `flag_weak_page`, `flag_missing_keyword` hesaplanır.
- **Faz B (AI enrichment biter bitmez):** `flag_duplicate_intent` hesaplanır (aynı cluster'a bakan sayfalar arasında aynı `primary_intent` var mı?).

### Pitfall 7: Re-Import — Orphan İşaretleme

**What goes wrong:** Re-import sırasında WP'de silinen sayfalar DB'de kalır ama orphan olarak işaretlenmez — kullanıcı silinen sayfaları "sağlıklı" sanır.
**Why it happens:** Upsert sadece gelen kayıtları günceller; gelmeyenlere dokunmaz.
**How to avoid:** Import loop bitmeden önce mevcut `wp_id`'leri topla; loop sonrası DB'deki eski kayıtları `imported_wp_ids.has(wp_id) === false` şartıyla `flag_orphan=true` olarak UPDATE et.

## Rate Limiting Strategy

Claude's Discretion alanı — önerilen yaklaşım:

```typescript
// Basit exponential backoff — WP sitelerinde 429 Too Many Requests için
async function fetchWithRetry(url: string, options: RequestInit, maxRetries = 3): Promise<Response> {
  for (let attempt = 0; attempt < maxRetries; attempt++) {
    const res = await fetch(url, options)
    if (res.status === 429) {
      const retryAfter = parseInt(res.headers.get('Retry-After') ?? '5', 10)
      await new Promise(r => setTimeout(r, retryAfter * 1000))
      continue
    }
    return res
  }
  throw new Error('Max retries exceeded')
}
```

**Batch arası bekleme:** 50ms delay her sayfa batch'i arasında — WP shared hosting'de DDoS koruması tetiklememek için.

[ASSUMED: Kesin rate limit değerleri WP kuruluma göre değişir — 50ms güvenli bir default]
