## Component Inventory

### 1. QaBadge (Extended)

**File:** `src/app/(dashboard)/projeler/[id]/sayfa-paketi/QaBadge.tsx`

**Changes:** Add `projectRules: Record<string, boolean>` prop. Extend `computeQaRules` to evaluate active rules from `rule-meta.ts`.

**Rendering contract:**

```
errors > 0  → <span class="... text-red-400">✕ Hata</span>
warnings > 0 → <span class="... text-amber-400">⚠ {N} Uyarı</span>
clean        → <span class="... text-emerald-400">✓ QA Geçti</span>
```

- Combined count: hardcoded rules + project rules failures summed together.
- `px-1.5 py-0.5 rounded text-[10px]` — identical to current implementation.
- `variant` prop: BANNED. Color via `className` only.

### 2. Score Row

**Location:** Editor header, below QaBadge and PackageStatusBadge row.

**Format:**
```
SEO 85 | İçerik 90 | İnsan 80 | Schema 60 | Hazırlık 79
```

**HTML structure:**
```tsx
<div className="flex items-center gap-1.5 text-[10px] text-muted-foreground">
  <span>SEO <span className={scoreColor(seo)}>{seo ?? '—'}</span></span>
  <span className="text-muted-foreground/40">|</span>
  <span>İçerik <span className={scoreColor(content)}>{content ?? '—'}</span></span>
  <span className="text-muted-foreground/40">|</span>
  <span>İnsan <span className={scoreColor(human)}>{human ?? '—'}</span></span>
  <span className="text-muted-foreground/40">|</span>
  <span>Schema <span className={scoreColor(schema)}>{schema ?? '—'}</span></span>
  <span className="text-muted-foreground/40">|</span>
  <span>Hazırlık <span className={scoreColor(readiness)}>{readiness ?? '—'}</span></span>
</div>
```

- When Claude QA has not run: `content` and `human` render as `—` in `text-muted-foreground`.
- `scoreColor(n)`: `n >= 80 → 'text-emerald-400'` / `n >= 60 → 'text-amber-400'` / `n < 60 → 'text-red-400'` / `null → 'text-muted-foreground'`
- Last QA run timestamp: optional, rendered as `text-[10px] text-muted-foreground` after the score row if `qa_scores.last_qa_run` is set — format: `"Son denetim: 14:32"`.

### 3. Rules Violation Dialog (pre-lock)

**Trigger:** "Kilitle" button click when rules violations exist.

**Dialog pattern:** Uses existing `Dialog` / `DialogTrigger` / `DialogContent` with `render={}` prop (NOT `asChild`).

**Title:** "Kural İhlalleri Tespit Edildi"

**Structure:**
```
DialogTitle: Kural İhlalleri Tespit Edildi
DialogDescription: Aşağıdaki kural ihlalleri bulundu. Yine de kilitlemek istiyorsan onaylayabilirsin.

[violation list — each item as inline span with severity color]
  ⚠ title_starts_with_keyword — Focus keyword başlıkta bulunamadı
  ✕ title_max_length_enforced — Başlık 60 karakteri aşıyor

[buttons row]
  <DialogClose render={<Button variant="ghost" size="sm">İptal</Button>} />
  <Button size="sm" onClick={proceedToQA}>Anlıyorum, yine de kilitle</Button>
```

- No hard block. User can always proceed.
- Violation items: `text-xs font-normal`. Severity icon prefix: `⚠` amber-400 for warning, `✕` red-400 for error.
- DialogContent: `max-w-sm`, `showCloseButton={false}`.

### 4. LLM QA Dialog (post-rules check)

**Trigger:** Automatic after rules check passes or user acknowledges violations.

**States:**

#### Loading state:
```
DialogTitle: Kalite Denetimi
[centered spinner or pulse animation]
<p class="text-sm text-muted-foreground text-center">Claude analiz ediyor...</p>
```

Spinner: use a simple CSS border-spin or existing shadcn Loader pattern. Size: 20px, `text-muted-foreground`.

#### Result state:
```
DialogTitle: Kalite Denetimi Sonucu

[4 check rows]
  ✓ Intent Uyumu          [ok → emerald-400]
  ⚠ Robotik Dil Riski    [warning → amber-400]
  ✕ Entity Eksikliği      [critical → red-400]
  ✓ Duplicate Risk        [ok → emerald-400]

[note text per item — text-xs text-muted-foreground, indented]

[buttons row — right aligned]
  <DialogClose render={<Button variant="ghost" size="sm">İptal</Button>} />
  <Button size="sm" onClick={handleLock}>Anlayarak Kilitle</Button>
```

**Check item structure:**
```tsx
<div className="space-y-1">
  <div className="flex items-center gap-2 text-sm">
    <span className={severityIcon(check.severity)} />
    <span className={severityClass(check.severity)}>{checkLabel[check.id]}</span>
  </div>
  {check.note && (
    <p className="text-xs text-muted-foreground pl-5">{check.note}</p>
  )}
</div>
```

**Severity mapping:**
- `ok` → icon `✓`, class `text-emerald-400`
- `warning` → icon `⚠`, class `text-amber-400`
- `critical` → icon `✕`, class `text-red-400`

**Check labels (Turkish):**
- `intent_drift` → "Intent Uyumu"
- `robotic_language` → "Robotik Dil Kontrolü"
- `entity_gap` → "Entity Kapsamı"
- `duplicate_risk` → "Duplicate Risk"

#### Error state:

## Interaction Flow Contract

```
[approved] Kilitle butonu
  └─ Client: computeQaRules(fields, projectRules)
       ├─ No violations → skip rules dialog → go to LLM QA
       └─ Violations found → open Rules Violation Dialog
            ├─ "İptal" → close, stay in approved state
            └─ "Anlıyorum, yine de kilitle" → go to LLM QA

  LLM QA
  └─ Open QA Dialog (loading state)
       └─ fetch POST /api/ai/qa-audit
            ├─ Success → render result state in same dialog
            │    ├─ "İptal" → close, stay in approved state
            │    └─ "Anlayarak Kilitle" → updatePackageStatus('locked') + save qa_scores
            └─ Error → render error state in same dialog
                 ├─ "İptal" → close, stay in approved state
                 └─ "Yine de Kilitle" → updatePackageStatus('locked') (no qa_scores written)
```

**State management:**
- `qaDialogOpen: boolean` — controls single Dialog open/close
- `qaDialogPhase: 'rules' | 'loading' | 'result' | 'error'` — controls which content renders inside
- One Dialog, content swaps in place — no nested or stacked dialogs
- `useTransition` + `router.refresh()` on successful lock
