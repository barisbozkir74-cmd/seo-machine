## Ekranlar ve Etkileşim Kontratı

### Karar: Cluster Panel Konumu

**Karar: Aynı sayfada toggle ile** — `/keyword-stratejisi` sayfasında "Düz Liste" / "Küme Görünümü" toggle butonları. Ayrı route AÇILMAZ.

**Gerekçe:** Phase 5'te oluşturulan düz tablo korunur, kullanıcı aynı sayfada iki görünüm arasında geçiş yapar. Ayrı route Phase 7 site tree için daha uygun bir pattern; clustering/scoring aynı veri üzerinde farklı görünüm.

**Toggle pattern:** Sayfa üstünde iki buton grubu — `<div className="flex rounded-md border border-border overflow-hidden">`. Sol: "Düz Liste", Sağ: "Küme Görünümü". URL query param: `?view=flat` (default) / `?view=cluster`. Server Component searchParams ile okur.

---

### Karar: Enrichment Uyarısı

**Karar:** Kümeleme tetiklenmeden önce `pendingEnrichment > 0` ise bir inline banner gösterilir. Banner clustering'i engellemez (buton aktif kalır), sadece bilgilendirir.

**Uyarı metni:** "X keyword henüz zenginleştirilmemiş — bunlar intent verisi olmadan sadece metin benzerliğiyle kümelenecek."

**Pattern:** `bg-amber-500/10 border border-amber-500/30 text-amber-400` banner, section header'ının altında, "Kümelere Böl" butonunun üstünde.

---

### Karar: Primary Keyword Seçimi

**Karar: Otomatik (en yüksek volume) + kullanıcı override.**

Sistem clusterAndScoreKeywords çalıştırdığında primary'yi otomatik atar. Küme panelinde her cluster'ın primary keyword satırında yıldız ikonu (HugeIcons: `Star01Icon` veya `StarIcon`) görünür. Kullanıcı başka bir keyword'ün satırındaki boş yıldıza tıklayarak primary'yi değiştirebilir (`setPrimaryKeyword` Server Action).

**Pattern:** Primary satır → `text-primary` (beyaz) dolu yıldız. Diğer satırlar → `text-muted-foreground opacity-0 group-hover:opacity-100` boş yıldız. İnteraktif — tıklanabilir.

### Ekran 1: Cluster Trigger UI

**Konum:** `keyword-stratejisi/page.tsx` — "Keyword Listesi" section'ının header'ında, sağ tarafta.

**Bileşenler:**
- `ClusterButton` — Client Component, `useTransition` ile loading state
- Buton metni: "Kümelere Böl" (idle) → "Kümeleniyor..." (pending)
- Loading state: `opacity-50` + animate-spin ikonu
- Buton: `variant="outline"` değil — bu primary action, dolayısıyla `className="bg-primary text-primary-foreground hover:bg-primary/90"` (veya shadcn default primary variant)
- Küme sayısı > 0 ise buton metni: "Yeniden Kümeleme" (RESEARCH.md Open Question 1 kararı)

**Enrichment uyarı banner'ı (opsiyonel):**
```
[amber border kutusu]
⚠ 12 keyword zenginleştirilmemiş — bunlar yalnızca metin benzerliğiyle kümelenecek.
```
`pendingEnrichment === 0` ise banner gösterilmez.

**"Kümelere Böl" sonrası başarı:** `revalidatePath` ile sayfa yenilenir. Ayrıca `{clusterCount} küme oluşturuldu` toast gösterilmez (Server Component ortamı) — sayfa yenilendikten sonra cluster panel otomatik güncellenmiş olur.

### Ekran 2: Düz Tablo (Flat View) — Opportunity Score Sütunu Ekleme

Mevcut 7 sütunlu tabloya **8. sütun** eklenir: **Skor**

**Yeni tablo sütunları (soldan sağa):**

| Kolon | Genişlik | İçerik |
|-------|---------- |--------|
| × (sil) | w-10 | KeywordDeleteButton — mevcut |
| Keyword | flex-1 | Keyword metni — mevcut |
| Volume | w-20, text-right | Formatlanmış hacim — mevcut |
| CPC | w-18, text-right | `$X.XX` format — mevcut |
| KD | w-16, text-right | Dot + etiket — mevcut |
| Küme | w-28 | bg-secondary badge — mevcut |
| **Skor** | **w-16, text-right** | **Yeni — opportunity score badge** |
| Intent | w-28 | IntentBadge — mevcut |

**Skor badge render kuralları:**
- `opportunity_score === null` → `—` (muted-foreground)
- `opportunity_score >= 70` → `bg-violet-500/20 text-violet-400 border-0` badge — "X.X"
- `opportunity_score >= 40` → `bg-amber-500/20 text-amber-400 border-0` badge — "X.X"
- `opportunity_score < 40` → `bg-secondary text-muted-foreground border-0` badge — "X.X"

Örnek: `<Badge className="bg-violet-500/20 text-violet-400 text-xs border-0">87.4</Badge>`

### Ekran 3: Küme Görünümü (Cluster Panel)

**Konum:** `?view=cluster` sorgu parametresiyle aynı sayfada toggle edilir.

**Layout:** Her cluster ayrı bir kart bloğu — `rounded-md border border-border bg-card`.

**Cluster kart anatomisi:**

```
┌─────────────────────────────────────────────────────────┐
│  [Küme adı — cluster_name]         [intent badge]  [×]  │  ← Cluster header — bg-secondary/40, p-3
│  ─────────────────────────────────────────────────────  │
│  ★  keyword-1 (primary)    12.4K   $2.10  Kolay   87.4  │  ← Primary satır — font-semibold keyword
│     keyword-2              8.2K    $1.80  Orta    61.2   │  ← Normal satır
│     keyword-3              3.1K    —      Zor     22.0   │
│  ─────────────────────────────────────────────────────  │
│  [Keyword Taşı]                          3 keyword       │  ← Footer
└─────────────────────────────────────────────────────────┘
```

**Cluster header:**
- Sol: `cluster_name` — `text-sm font-semibold`
- Orta: intent badge (IntentBadge component, küme intent'i)
- Sağ: `ClusterDeleteButton` — mevcut pattern (opacity-0 hover'da görünür)

**Keyword satırları (cluster içinde mini tablo):**
- Primary keyword satırı: yıldız ikonu `text-primary` + keyword `font-semibold`
- Diğer keyword satırları: boş/hover yıldız `opacity-0 group-hover:opacity-100` + keyword `font-normal`
- Sütunlar: [★] [Keyword] [Volume] [CPC] [KD] [Skor] — aynı genişlik oranları
- TableRow `className="group"` — hover'da yıldız ve "Taşı" opsiyonu görünür

**Küme bulunamadı (boş durum):**
```
Henüz küme oluşturulmadı.
"Kümelere Böl" butonuna basarak keyword'leri otomatik gruplandır.
```

### Ekran 4: MoveKeywordDialog

**Tetikleyici:** Cluster panel'de her keyword satırında hover'da `[Taşı →]` button görünür — `text-xs text-muted-foreground opacity-0 group-hover:opacity-100 transition-opacity`.

**Dialog:** shadcn Dialog — base-ui render prop pattern (asChild değil, mevcut pattern):

```tsx
<DialogTrigger render={<button className="...">Taşı</button>}>
```

**Dialog içeriği:**

Başlık: `"{keyword}" kümesini değiştir`

İçerik: Mevcut cluster'lar listesi — radio group veya basit buton listesi. Her cluster için:
```
○  Küme adı (intent badge)    [3 keyword]
```

Mevcut cluster: seçili gösterilir ama tıklanamaz (disabled, muted stil).

Footer: "İptal" (ghost) + "Taşı" (primary, disabled — seçim yapılmadan).

**Loading state:** "Taşı" butonuna basınca: `opacity-50` + `useTransition` pending.

**Başarı:** Dialog kapanır, `revalidatePath` ile sayfa güncellenir. Ayrı toast yok.

**Hata:** Dialog içinde satır olarak: `<p className="text-sm text-destructive">{error}</p>`

**Boş cluster listesi (tüm keyword'ler aynı cluster'da):** "Başka küme yok. Önce 'Kümelere Böl' ile yeni kümeler oluşturun."

## Established Patterns (Mandatory)

Executor aşağıdaki kurallara harfiyen uymak zorundadır:

1. **Badge renk ataması:** `className="bg-X-500/20 text-X-400 border-0"` — `variant` prop kullanılmaz (D-11)
2. **Font:** Yalnızca `font-normal` ve `font-semibold` — `font-medium` yasak (05-SUMMARY.md)
3. **Dialog trigger:** `DialogTrigger render={<button>}` — `asChild` base-ui'da desteklenmez
4. **TableRow hover:** `className="group"` + child butonlarda `opacity-0 group-hover:opacity-100`
5. **Loading state:** `opacity-50` + `animate-spin` SVG ikonu — skeleton loader kullanılmaz
6. **Silme işlemleri:** `confirm()` dialog yok — anında sil + visual feedback (D-12)
7. **Silme rengi:** `text-destructive` / `bg-destructive` — yalnızca destructive action için
8. **Server Action hata:** Dialog içinde `<p className="text-sm text-destructive">` — toast yok
9. **Renk paleti:** Zinc değil `slate` (projenin base color); ikincil `emerald/amber/red/violet/orange/blue/gray` semantic renk olarak
10. **Ownership doğrulama:** Her Server Action: `getUser()` + `project_id + user_id` üçlüsü
