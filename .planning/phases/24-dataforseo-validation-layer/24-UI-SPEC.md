Hem light, hem standart, hem deep analiz tetiklendiğinde bu dialog açılır.

| State | Koşul | Görsel |

## State Machine — Polling Lifecycle (Deep Analysis)

`DeepAnalysisPoller.tsx` bileşeni, yalnızca `workflow_runs.status IN ('pending', 'running')` olduğunda aktiftir.

| Adım | Koşul | Davranış |
|------|-------|---------|
| Başlatma | `status = 'pending'` | 5 saniye interval başlar, `router.refresh()` her intervalda |
| Devam | `status = 'running'` | Polling sürer |
| Tamamlanma | `status = 'done'` | `clearInterval()`, success mesajı 5 saniye gösterilir, `router.refresh()` |
| Hata | `status = 'failed'` | `clearInterval()`, hata mesajı gösterilir |
| Timeout (12 dakika) | Polling 144 döngü sonra durur | "Analiz yanıt vermedi. Sayfayı yenileyin." mesajı |

Stop conditions özeti: completed / failed / timeout (12 dakika, 144 × 5 saniye)

Pattern: `ResearchAutoTrigger.tsx` ile aynı (`setInterval` + `router.refresh()`) — kaynak doğrulandı.

## Interaction Contracts

### Temel Verileri Al — Tam Akış

1. Kullanıcı "Temel Verileri Al"a tıklar
2. Concurrent guard kontrolü — aktif iş var mı?
   - Evet: butona tıklama engellenir (disabled state aktif, tooltip gösterilir)
   - Hayır: devam
3. Cost approval dialog açılır (`open-light` state)
4. Kullanıcı "Temel Analizi Başlat"a tıklar → dialog `confirming` state'e geçer
5. Server Action başlatılır (`useTransition`)
6. `dfs_fetched_at` güncellemesi tablo SSR yenilenmesiyle yansır
7. Sonuç inline mesajı gösterilir (4 saniye), `router.refresh()` çağrılır

### Derinlemesine Analiz — Tam Akış

1. Kullanıcı "Derinlemesine Analiz"e tıklar
2. Concurrent guard kontrolü
3. Cost approval dialog açılır (`open-deep` — kırmızı uyarı banner dahil)
4. Kullanıcı "Derinlemesine Analizi Başlat"a tıklar
5. POST `/api/dataforseo/deep-analysis/route.ts` çağrılır
6. `workflow_runs` tablosuna `status='pending'` satırı INSERT edilir
7. n8n webhook tetiklenir
8. `DeepAnalysisPoller` mount edilir — 5 saniye polling başlar
9. `workflow_runs.status = 'running'` → "Derinlemesine Analiz" butonu `running` state'e geçer
10. `workflow_runs.status = 'done'` → polling durur, başarı mesajı, `router.refresh()`
11. `workflow_runs.status = 'failed'` → polling durur, hata mesajı

### Tekil ve Toplu Analiz (Aynı Kontrat)

- Cluster görünümünde: seçili cluster'daki tüm keywordler batch olarak işlenir
- Liste görünümünde: seçili keywordler (checkbox ile seçilmiş) batch olarak işlenir
- Seçim yoksa: tüm proje keywordleri işlenir (light/standard için max ~50)
- Her iki durumda da cost dialog aynı — sadece `count` değeri değişir

### Keyboard / Focus

- Tüm analiz butonları `<button>` elementi — native tab sırası
- Dialog açıkken focus trap: shadcn Dialog'ın native Radix UI focus management'ı kullanılır
- Dialog'da Enter = onay butonu aktive edilmez (kazara onay riski) — kullanıcı butonunu tıklamalı
- `disabled` attribute (CSS-only değil) — tüm guard state'lerinde

## Accessibility

- Analiz butonları: `title` attribute tüm state'lerde mevcut (concurrent guard, disabled nedeni)
- `disabled` state: `disabled` HTML attribute kullanılır, CSS-only `pointer-events-none` yeterli değil
- Cyan-400 on dark (#020817): WCAG 3:1 non-text UI kontrastını karşılar (dekoratif rol)
- Amber uyarı metni `text-amber-300` on `#020817`: WCAG AA karşılar (4.5:1+)
- Cost dialog'da maliyet rakamı `text-cyan-400`: bilgi metni, `aria-describedby` ile `DialogDescription`'a bağlı
- Badge ("Veri yok", "Güncel değil"): `role` attribute gerektirmez, `title` tooltip yeterli
