# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1: Foundation.
> Generated by gsd-ui-researcher. Scope: login page + signup page only.
> No dashboard UI is built until Phase 2.

---

## Scope

This phase delivers exactly two UI surfaces:

| Surface | Route | Purpose |
|---------|-------|---------|
| Login page | `/login` | Email + password sign-in form |
| Signup page | `/signup` | Email + password registration form |

All other Phase 1 work (database schema, RLS policies, API key storage, middleware) is backend-only and has no UI surface. This contract governs the auth screens exclusively.

## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline label spacing |
| sm | 8px | Input icon padding, helper text gap |
| md | 16px | Default form field spacing, card padding horizontal |
| lg | 24px | Card padding vertical, between-field gap |
| xl | 32px | Card width constraint padding |
| 2xl | 48px | Auth card vertical centering offset |
| 3xl | 64px | Page-level vertical centering |

Exceptions: Touch targets on interactive elements must be minimum 44px height (accessibility). shadcn `Button` default satisfies this at `h-10` (40px) — override to `h-11` (44px) on the submit button.

## Typography

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px | 400 (regular) | 1.5 | Input placeholder, helper text, descriptive copy |
| Label | 14px | 500 (medium) | 1.4 | Form field labels, error messages |
| Heading | 24px | 600 (semibold) | 1.2 | Page heading ("Sign in to SEO Machine") |
| Display | 14px | 400 (regular) | 1.5 | Footer link copy ("Don't have an account?") |

Font family: `Inter, ui-sans-serif, system-ui, -apple-system, sans-serif`

Maximum 2 weights in use per screen: 400 (regular) for body/display and 600 (semibold) for headings. Labels use 500 only because shadcn ships this; treat it as part of the "semibold tier" visually.

## Color

Palette is Slate-based (shadcn default Slate). Dark mode is the primary mode for this internal agency tool.

| Role | CSS Variable | Dark Value | Usage |
|------|-------------|------------|-------|
| Dominant (60%) | `--background` | `#020817` (Slate 950) | Page background, full-bleed surface |
| Secondary (30%) | `--card` | `#0f172a` (Slate 900) | Auth card background, input background |
| Accent (10%) | `--primary` | `#f8fafc` (Slate 50) | Submit button background, active focus ring |
| Destructive | `--destructive` | `#ef4444` (Red 500) | Error messages, invalid field borders |
| Muted text | `--muted-foreground` | `#64748b` (Slate 500) | Placeholder text, secondary link copy |
| Border | `--border` | `#1e293b` (Slate 800) | Input borders, card border |
| Foreground | `--foreground` | `#f8fafc` (Slate 50) | Primary text on dark background |

Accent (`--primary`) is reserved for: submit button only (one per page). No other interactive element uses the accent color. Links use `--muted-foreground` underlined, not accent.

**60/30/10 breakdown:**
- 60% `--background`: page canvas
- 30% `--card`: auth card, inputs
- 10% `--primary`: one submit button per page

## Layout

Auth pages use a centered-card layout. No sidebar, no navigation, no header.

```
┌─────────────────────────────────────┐  ← --background fills 100vh
│                                     │
│       ┌─────────────────────┐       │
│       │  [Logo / App name]  │       │
│       │                     │       │  ← --card, max-w-sm (384px), rounded-lg
│       │  [Heading]          │       │
│       │  [Subheading]       │       │
│       │                     │       │
│       │  Email field        │       │
│       │  Password field     │       │
│       │  [Submit button]    │       │
│       │                     │       │
│       │  [Switch link]      │       │
│       └─────────────────────┘       │
│                                     │
└─────────────────────────────────────┘
```

Card: `max-w-sm w-full mx-auto`, `px-8 py-10`, vertically centered via `min-h-screen flex items-center justify-center`.

## Interaction States

Every input must implement all four states:

| State | Visual |
|-------|--------|
| Default | `--border` border, `--card` background |
| Focused | `ring-2 ring-primary ring-offset-2` (shadcn default focus) |
| Error | `border-destructive`, red `FormMessage` below field |
| Disabled | `opacity-50 cursor-not-allowed` on button during submission |

Submit button states:

| State | Visual |
|-------|--------|
| Default | `bg-primary text-primary-foreground` |
| Hover | `bg-primary/90` (shadcn default) |
| Loading/submitting | `disabled` + spinner icon (`Loader2` from lucide-react, `animate-spin`) |
| Disabled | `opacity-50 cursor-not-allowed` |

## Copywriting Contract

### Login page

| Element | Copy |
|---------|------|
| Page `<title>` | `Sign in — SEO Machine` |
| Heading | `Sign in to SEO Machine` |
| Subheading | `Enter your email and password to continue.` |
| Email label | `Email` |
| Password label | `Password` |
| Primary CTA | `Sign in` |
| Loading CTA | `Signing in...` |
| Switch link | `Don't have an account? Sign up` |

### Signup page

| Element | Copy |
|---------|------|
| Page `<title>` | `Create account — SEO Machine` |
| Heading | `Create your account` |
| Subheading | `Enter your email and password to get started.` |
| Email label | `Email` |
| Password label | `Password` |
| Primary CTA | `Create account` |
| Loading CTA | `Creating account...` |
| Switch link | `Already have an account? Sign in` |

### Error states

| Trigger | Copy |
|---------|------|
| Invalid email format | `Enter a valid email address.` |
| Empty email | `Email is required.` |
| Empty password | `Password is required.` |
| Password too short (< 8 chars) | `Password must be at least 8 characters.` |
| Wrong email or password (login) | `Incorrect email or password. Check your credentials and try again.` |
| Email already in use (signup) | `An account with this email already exists. Sign in instead.` |
| Network / unknown error | `Something went wrong. Please try again.` |

Error copy appears in `FormMessage` below the relevant field. Authentication errors (wrong password, duplicate email) appear in a `FormMessage` below the submit button or as a top-of-form alert — not in a toast.

### Empty states

Not applicable for Phase 1 — auth forms have no empty data states.

### Destructive actions

None in Phase 1. No delete confirmations, no dangerous operations on auth screens.

## Accessibility Requirements

- All inputs have explicit `<Label>` with matching `htmlFor`/`id`
- Error messages are announced via `aria-describedby` linking input to `FormMessage` (shadcn `Form` handles this automatically)
- Submit button must not be the only keyboard-accessible CTA — Tab order: email → password → submit → switch link
- Page has a single `<h1>` matching the heading copy above
- Color contrast: Slate 50 on Slate 950 background = 19.5:1 (exceeds WCAG AA 4.5:1)
- Minimum touch target: 44px height on submit button (override shadcn default `h-10` to `h-11`)

## What is NOT in this UI-SPEC

The following are explicitly out of scope for Phase 1 and should not be implemented:

- Dashboard layout, navigation, sidebar
- Project list or any data display
- Any page under `/dashboard`
- Password reset / forgot password flow (deferred)
- OAuth / social login buttons (out of scope per D-02)
- Loading skeletons, data tables, modals

These will be specified in Phase 2 UI-SPEC.
