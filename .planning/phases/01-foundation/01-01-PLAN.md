## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → Next.js server | Form submissions cross this boundary; user-controlled input |
| Next.js server → Supabase | Auth credentials transmitted; JWT tokens returned |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Spoofing | login-form.tsx auth call | mitigate | Supabase handles credential verification; no plaintext password storage client-side |
| T-01-02 | Information Disclosure | .env.local | mitigate | .env.local in .gitignore (create-next-app default); .env.local.example committed instead — no real keys in git |
| T-01-03 | Tampering | form input fields | mitigate | Zod schema validation on all inputs before any API call; email format enforced, password min-length enforced |
| T-01-04 | Elevation of Privilege | /dashboard route | accept | Route protection implemented in Plan 04 middleware; this plan creates static pages only — no protected data accessible yet |
| T-01-05 | Information Disclosure | Browser bundle | mitigate | NEXT_PUBLIC_ prefix only for Supabase URL and anon key (safe to expose per Supabase architecture); secret keys never set as env vars (handled in Plan 02/03 via Vault) |
</threat_model>
