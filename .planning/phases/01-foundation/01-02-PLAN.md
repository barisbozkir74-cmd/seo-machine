First, the shared trigger function (created once, applied to all tables):

```sql
-- Shared trigger function for updated_at
CREATE OR REPLACE FUNCTION public.set_updated_at()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = now();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;
```

**1. projects** — Core entity; all other tables reference it

  name          TEXT NOT NULL,
  domain        TEXT NOT NULL,
  sector        TEXT,
  target_country TEXT,
  target_language TEXT,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SQL migration → Supabase Postgres | Schema DDL executed with elevated privileges during migration |
| application → public schema tables | All future data access goes through these table definitions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01 | Elevation of Privilege | user_id column on all tables | mitigate | `user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE NOT NULL` enforced at DB level; RLS in Plan 03 adds the application-layer guard |
| T-02-02 | Information Disclosure | JSONB columns (top_pages, gap_report, etc.) | mitigate | RLS policies in Plan 03 ensure users can only query their own rows; JSONB columns do not bypass row-level security |
| T-02-03 | Tampering | ON DELETE CASCADE chains | accept | Cascade is intentional: deleting a project removes all child data. No recovery needed per D-06 (hard deletes). User must confirm project deletion in UI (Phase 2). |
| T-02-04 | Denial of Service | Unindexed FK columns | mitigate | Supabase auto-indexes PKs. Add index on project_id and user_id columns for query performance — include `CREATE INDEX` statements on high-traffic FK columns (projects.user_id, keywords.project_id, pages.project_id) |
</threat_model>
