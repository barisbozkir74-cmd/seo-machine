## Component Inventory

This phase extends existing components. No new shadcn components are installed.

### New Component: `KeywordChatHeader` (part of KeywordChat refactor)

The existing KeywordChat panel header gains a "Yenile" button. The header row currently renders:
```
[chat icon] AI Asistan          [collapse chevron]
```

After Phase 23 it renders:
```
[chat icon] AI Asistan     [Yenile btn]  [collapse chevron]
```

**Yenile Button Spec:**
- Element: `<button>` (no shadcn Button — keeps weight consistent with existing icon buttons in the header)
- Label: "Yenile" — text only, no icon (fits compact header space)
- Idle state: `text-xs text-violet-400 hover:text-violet-300 transition-colors`
- Loading/streaming state: button disabled + label changes to "Analiz ediliyor..." + spinning SVG replaces label (same spinner pattern used in AiAcquireButton)
- Position: between the title and the collapse chevron
- Padding: `px-2 py-0.5` to match header density
- Width: intrinsic (shrink-0)
- Disabled condition: while `isStreaming === true`

### Proactive First-Load State

When the page first loads and analysis has not yet run (or data changed since last run):

- Auto-trigger fires immediately on mount (`useEffect` with `last_analyzed_at` localStorage check)
- No banner, no toast — the streaming dots appear directly in the chat message area as the first message (role: `assistant`)
- The existing empty-state starters panel (`STARTERS` buttons) is suppressed while streaming or when messages already exist — this is the existing behavior and requires no change

### Primary AI Message (first assistant message)

- Role: `assistant` — uses existing message bubble style unchanged
- No prefix label or badge before the message — the content itself opens with strategic context (e.g. "Keyword stratejini analiz ettim…")
- Streaming: uses existing animated dots pattern (3 bouncing dots) while content is empty
- Content format: plain text with `whitespace-pre-wrap` — existing rendering, no markdown parser added

### Review AI Message (second assistant message, appended automatically)

- Role: `assistant` — same bubble style as Primary AI message
- Prefix label: a small inline label "Denetim:" rendered in `text-violet-400 font-medium` at the start of the message content, before the actual review body
- Content: plain text with `whitespace-pre-wrap`
- Appended immediately after Primary AI message finishes streaming — no user action required
- Streaming: uses same animated dots pattern while Review content is empty (second message pre-appended to state with empty string while Review AI streams)

### State Machine for KeywordChat (Phase 23 additions)

| State | UI Appearance |
|-------|--------------|
| `idle` (no messages, no analysis run) | Existing starters panel |
| `analyzing-primary` | Starters panel hidden; first assistant message visible with streaming dots; Yenile button disabled (label: "Analiz ediliyor...") |
| `analyzing-review` | Primary message complete; second assistant message appended with streaming dots; Yenile button disabled |
| `complete` | Both messages rendered; Yenile button re-enabled |
| `error` | Single assistant message with text: "Analiz başarısız oldu. Yenile butonuna tıklayarak tekrar dene." |

## Interaction Contracts

### Auto-trigger on First Load

1. `KeywordChat` (or its parent shell) reads `localStorage` key `kwai_analyzed_{projectId}`
2. If key is absent or stored `last_analyzed_at` is older than the most recent keyword/cluster mutation timestamp: trigger analysis immediately on mount
3. Trigger calls server action → streams Primary AI response as first message → streams Review AI response as second message → stores `last_analyzed_at` in localStorage
4. User sees no loading screen — first message streaming dots appear in the chat panel naturally

### Yenile Button Trigger

1. User clicks "Yenile"
2. Existing messages are cleared from state
3. Analysis pipeline re-runs identically to first-load trigger
4. `last_analyzed_at` in localStorage is updated on completion

### Streaming Behaviour

- Primary AI: single `fetch` to new API endpoint (e.g. `/api/keywords/analyze`) — streaming response, identical pattern to existing `/api/keywords/chat` fetch/ReadableStream loop
- Review AI: appended as second message immediately after Primary stream ends — either as a second fetch or second phase in same stream (implementation detail, not UI contract)
- Both use existing animated dots pattern: `animate-bounce` with staggered `animation-delay` on three `·` spans
- Auto-scroll: existing `bottomRef.current?.scrollIntoView({ behavior: 'smooth' })` fires on every `setMessages` call — handles both Primary and Review streaming automatically

### Focus Management

- No focus trap changes
- Yenile button is keyboard-accessible (`button` element, natural tab order in header)
- Input `textarea` remains focusable during streaming but `disabled` prop set to true (existing `isStreaming` guard)
