## Interaction Contract

### 1. "Projeyi Başlat" Button — ProjectInfoSection

Placement: Bottom of `ProjectInfoSection`, below all editable fields. Separated by a `<Separator />` with `mt-4 mb-3` spacing.

**State machine:**

| State | Condition | Visual |
|-------|-----------|--------|
| `disabled` | Any of: `!sector`, `!initial_competitors`, `!target_keywords` | `variant="default"` + `disabled` prop → opacity-50, pointer-events-none (built-in to buttonVariants) |
| `enabled` | All 3 gate fields non-empty | `variant="default"`, full opacity |
| `loading` | After click, before API response | `disabled={true}` + `<Loader2 className="animate-spin" />` icon + label "Araştırılıyor..." |
| `completed` | `research_status === 'completed'` in project data | Replace button with completed state block (see below) |

**Disabled inline hint** (shown only when button is disabled):

```
Eksik: {comma-separated list of missing field labels}
```

- Typography: 12px (text-xs), weight 400 (normal), color `text-muted-foreground`
- Placement: Directly below the button, `mt-2` (8px)
- Field label mapping: `sector` → "sektör", `initial_competitors` → "rakipler", `target_keywords` → "hedef kelimeler"
- Example: "Eksik: sektör, rakipler"
- Do NOT show the hint when button is enabled.

**Completed state block** (replaces button after successful research):

```
[rounded-lg border border-emerald-500/30 bg-emerald-500/5 p-3]
  Araştırma tamamlandı  ✓
  [text-xs text-muted-foreground mt-2]
  Sonuçları görüntülemek için → Araştırma sayfasına git  [link]
```

- Matches `StageTransition` completed state pattern exactly.
- Link: `href="/projeler/{id}/arastirma"`, `text-sm text-muted-foreground hover:text-foreground`
- No button; only the completed block.
- If user edits a gate field after research is complete, completed block remains (no re-gating).

**Loading UX:**
- User stays on the same page (no navigation).
- Button becomes disabled + shows spinner during the API call.
- No progress bar, no SSE — spinner only (D-04 decision).
- After completion: toast success + completed block replaces button.
- After error: toast error + button returns to enabled state.

---

### 2. Toast Notifications

Use the existing project toast pattern (identify from codebase; do not introduce a new toast library).

| Event | Type | Message |
|-------|------|---------|
| Research started | — | No toast at start; just button loading state |
| Research completed | success | "Araştırma tamamlandı. Araştırma sayfasında sonuçları görebilirsiniz." |
| Research failed — API error | error | "Araştırma başarısız oldu. Lütfen tekrar deneyin." |
| Research failed — missing SerpAPI key | error | "SerpAPI anahtarı yapılandırılmamış. Lütfen sistem ayarlarını kontrol edin." |

Toast duration: default (auto-dismiss). No persistent banners.

---

### 3. "Yeniden Araştır" Button — /arastirma Page

Placement: Page header area of `/arastirma` page, right-aligned next to the `h1` ("Araştırma"). Use `flex justify-between items-center` wrapper around the existing `h1`.

**State machine:**

| State | Condition | Visual |
|-------|-----------|--------|
| `enabled` | Default (always available on /arastirma) | `variant="outline"` `size="sm"` |
| `loading` | After click, before API response | `disabled={true}` + `<Loader2 className="animate-spin" />` + "Araştırılıyor..." |

- No disabled gate on /arastirma — if the user is on this page, they already passed the gate.
- Same toast pattern as above on success/error.
- After success: page data refreshes (server revalidation); no navigation.

## Layout Contract

```

  ↓
<Separator className="my-4" />
[launch gate block]
  <Button variant="default" size="default" className="w-full"> Projeyi Başlat </Button>
```
