| Status | className | Turkish Label |

## Component Inventory

### Content Tab Bar (new component: `ContentTabBar`)

A secondary tab bar that sits below PeriodTabBar and switches between the three content sections. It is separate from PeriodTabBar (period selection remains independent and always visible at top).

```
Tabs: Cluster Performansı | Sayfa Performansı | Recovery
```

Pattern: mirrors PeriodTabBar layout — `inline-flex items-center gap-1 bg-card border border-border rounded-lg p-1`. Active tab: `bg-secondary text-foreground font-medium`. Inactive: `text-muted-foreground hover:text-foreground`. Button size: `px-4 py-2 rounded-md text-sm transition-colors min-h-[44px]`.

State: controlled via URL searchParam `?tab=recovery` (default: cluster). No client-side state — SSR navigation.

### Recovery Task Table (`RecoveryTaskTable`)

shadcn `<Table>` component. Columns:

| Column | Width | Content |
|--------|-------|---------|
| Sayfa | flex-1 | Title (text-sm font-normal) stacked above URL (text-xs text-muted-foreground truncate) |
| Pozisyon Kaybı | w-28, text-right | "+N.N pozisyon" in text-red-400, tabular-nums |
| Durum | w-32 | Status badge (see Badge Color Contract) |
| Aksiyon | w-24, text-right | "Güncelle" button |

Table header row: `text-xs font-normal uppercase text-muted-foreground` — matches PageMetricsTable header pattern.

Row hover: `hover:bg-muted/50 transition-colors` — matches PageMetricsTable row pattern.

### "Güncelle" Button

shadcn `<Button>` variant, size small. Use `variant="outline"` with `size="sm"`. On click: navigates to target route AND fires server action to set `status = 'in_progress'`.

- page_package source: navigates to `/projeler/[id]/sayfalar` (page list, user selects the page)
- imported_page source: navigates to `/projeler/[id]/site-analizi`

Button label: "Güncelle" (Turkish, no emoji).

### "Dismissed'ı Göster" Toggle

A text-style toggle button below the table (not above). Default state: dismissed tasks hidden. On click: reveals dismissed rows inline (no page navigation).

Pattern: `<button>` with `text-sm text-muted-foreground hover:text-foreground underline-offset-4 hover:underline` — no border, no background. Label: "Dismissed görevleri göster" / "Dismissed görevleri gizle".

### "Görmezden Gel" Dismiss Action

Each row in `open` or `in_progress` status has a secondary dismiss action. Rendered as a small text button or icon button at the trailing edge of the row (after "Güncelle"). Label: "Görmezden Gel". No modal confirmation — single click fires server action to set `status = 'dismissed'`. Destructive styling: `text-muted-foreground hover:text-red-400 transition-colors text-xs`.

No confirmation dialog is needed — dismissed tasks are recoverable via the "Dismissed'ı göster" toggle (they are not deleted).

### Empty State

Displayed when `recovery_tasks` returns 0 active rows (open + in_progress count = 0):

```
<div className="rounded-lg border border-border bg-card p-8 text-center">
  <p className="text-base font-semibold">Tespit edilen pozisyon düşüşü yok</p>
  <p className="text-sm text-muted-foreground mt-2">Sayfalar sağlıklı görünüyor.</p>
</div>
```

Pattern: matches izleme/page.tsx GSC not-connected empty state and PageMetricsTable empty state.

## Layout Structure

The izleme page layout is unchanged: `flex flex-col h-screen` outer, `w-64 shrink-0 border-r` sidebar, `flex-1 min-w-0 overflow-y-auto p-8` main content.

Inside the main content area, the `space-y-8` wrapper gains a 3rd section:

```
<div className="space-y-8">
  <PeriodTabBar projectId={id} active={period} />
  <ContentTabBar projectId={id} active={tab} />   {/* NEW */}

  {tab === 'cluster' && (
    <section>
      <h2 className="text-base font-semibold mb-4">Cluster Performansı</h2>
      <ClusterSummaryTable clusters={clusters} />
    </section>
  )}

  {tab === 'pages' && (
    <section>
      <h2 className="text-base font-semibold mb-4">Sayfa Performansı</h2>
      <PageMetricsTable pages={pages} />

  )}

  {tab === 'recovery' && (
    <section>
      <h2 className="text-base font-semibold mb-4">Recovery</h2>

    </section>

</div>
```

The `ContentTabBar` uses `?tab=cluster|pages|recovery` searchParam. Default (no param): `cluster` (backward compatible — existing behavior preserved).

## Interaction Contract

### URL State Machine

```
/projeler/[id]/izleme                       → tab=cluster (default), period=28
/projeler/[id]/izleme?period=7              → tab=cluster, period=7
/projeler/[id]/izleme?tab=recovery          → tab=recovery, period=28
/projeler/[id]/izleme?tab=recovery&period=7 → tab=recovery, period=7
```

Both `tab` and `period` params are independent. PeriodTabBar preserves current `tab` when switching period. ContentTabBar preserves current `period` when switching tab.

### "Güncelle" Click Flow

1. User clicks "Güncelle" on a recovery task row
2. Client fires Server Action: `updateRecoveryTaskStatus(taskId, 'in_progress')`
3. Server Action updates `recovery_tasks.status = 'in_progress'`
4. `router.push(targetRoute)` — navigates to editor
5. On return to izleme, row shows `in_progress` badge

### "Görmezden Gel" Click Flow

1. User clicks "Görmezden Gel" on a row
2. Client fires Server Action: `updateRecoveryTaskStatus(taskId, 'dismissed')`
3. Row disappears from default view (no loading spinner needed — optimistic removal acceptable)
4. "Dismissed görevleri göster" toggle allows recovery of context

### Automatic Resolved Transition (no UI action)

When `publishToWordPress` server action fires for a `page_packages` source task:
- `recovery_tasks` row for that `source_id` transitions to `status = 'resolved'`
- Resolved tasks are NOT shown in the default Recovery tab view
- Planner decides whether to surface resolved tasks at all (out of scope for this spec)
